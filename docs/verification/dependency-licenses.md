# Dependency license gate

CI installs cargo-deny 0.20.2 from the upstream release archive, verifies the archive SHA-256 against the platform-specific pinned value, then invokes the installed binary explicitly with the repository policy and `--locked`. Linux uses the x86_64 musl release archive (SHA-256 `9f12ed4c49936e09b48bf862b595cde2fe64fcbd9d74dfacac6131ca824c8d5f`); Windows uses the x86_64 MSVC archive (SHA-256 `975a22143262fd27476d19ee00c7af67978426e40e1dee94eed6bbade1cf87dc`). These values and release identity are user-verified inputs; CI does not rely on the cargo-deny action, whose cited implementation does not verify downloaded checksums or add `--locked`.

The SPDX expression behavior below is expected cargo-deny policy semantics, not behavior observed in this change. `MIT OR Apache-2.0` is expected to permit a package when either alternative is allowed; `MIT AND Apache-2.0` is expected to require both licenses to be allowed. These expression details, including OR evaluation against cargo-deny 0.20.2, remain pending parent-run CI proof. Third-party copyright notices and source-distribution obligations require separate review. Modified or copied dependency sources also require separate review of their provenance, license texts, notices, and applicable obligations; a license allowlist does not perform that review. This gate makes no legal-compliance claim.

Focused CI regression tests cover checksum rejection before extraction, missing/malformed provenance, propagation of the actual check exit status, and structural assertions for fail-closed report/upload wiring. The assertions do not execute GitHub Actions; runtime report or artifact-upload failure propagation remains untested until parent-run CI. No local execution was performed.

CI runs the check on Linux and Windows, but whether cargo-deny selects host-specific or broader target dependencies for this invocation is not verified; do not infer complete target-triple coverage. The actual `cargo-deny` CLI option ordering, configuration semantics, target graph selection, SPDX evaluation details, failure behavior, and current policy outcome have not been independently exercised or verified in this change. The archive extraction layout is also assumed from the provided release identity and has not been verified. Parent-run CI must validate these assumptions. A passing check is not legal advice or proof that obligations, attribution, notices, distribution terms, or every embedded/copied component have been satisfied.

The report operation requires the license log, Cargo manifest and lockfile, Cargo metadata and graph receipt, plus all six product preparation receipts: backend, relay, swarm, DNS, resolver, and Kademlia. These receipts cover the product preparation patches; conditional P08 receipts are not used as required product evidence. Missing or invalid receipt evidence fails report generation. The composite action report and artifact-upload steps both run with `always()`; upload uses `if-no-files-found: error`. The outcome is enforced at the end of the checks job, after the normal checks and conditional P08 steps, preserving failure behavior while allowing those checks and report upload to run.

Archive downloads and extraction use a newly created isolated temporary directory for each invocation. The downloaded archive's SHA-256 is checked before extraction; extraction layout and CLI option ordering are assumptions, not verified by local execution. Parent-run GitHub CI must validate the layout, CLI behavior and graph coverage. No local execution, network access, Cargo commands, builds, tests, or project execution was performed for this change.

## Local Linux execution and allowlist decision (2026-10-28)

The paragraphs above describe the change as authored. With explicit owner permission, the gate was then executed locally on Linux (Rust 1.99.1) after merging into `develop`; Windows was not exercised and the GitHub Actions report/upload wiring was not run. The regression suites passed (28 tests). `install` downloaded the Linux musl archive, verified its pinned SHA-256 and extracted the binary with the assumed layout. `report` produced all twelve expected files, including the six product preparation receipts.

With the original `MIT`/`Apache-2.0` allowlist, `check` failed: 35 locked-graph packages declare other licenses (Unicode-3.0, BSD-3-Clause, BSD-2-Clause, ISC, Zlib, Unlicense, CDLA-Permissive-2.0, and the compound expressions `Apache-2.0 AND ISC` and `(MIT OR Apache-2.0) AND Unicode-3.0`). This also showed AND expressions being evaluated per term. The owner requested that only licenses compatible with distributing this project under `MIT OR Apache-2.0` be allowed. The allowlist now adds exactly those seven permissive licenses; with it, `check` reports `licenses ok` with no warnings. Copyleft and unknown licenses remain denied. Keeping the dependencies' license texts and copyright notices in distributions remains a separate obligation, as described above.

The provenance receipts help identify selected upstream archive and patch inputs, but they are not a complete source-history record and do not prove cargo-deny checked those prepared source trees: their relationship to the configured graph is not established here. In particular, checks of modified/copied sources, retained third-party notices and license texts, and distribution obligations remain separate work. `--locked` prevents lockfile updates, but alone does not prove complete or reproducible dependency resolution; registry access may still be needed. No legal-compliance conclusion follows from the gate or its artifact.
