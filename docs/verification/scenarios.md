# Матрица сценариев проверки Sha’ar Stack (P01)

Дата: 2026-10-21. Оговорка: на этапе P01 ничего не запускалось —
ни тесты, ни сборки, ни эксперименты. Все статусы P01 в таблицах —
«план». Обозначения уровня: unit — детерминированный тест;
CI-стенд — управляемый стенд в CI; P03 — блокирующий эксперимент
(development.md 4.2); ручной — реальный NAT, вне CI, по разрешению
пользователя.

## 1. iroh custom transport и signaling-only

Gate P03: установление соединения, обмен кандидатами, переход на прямой
UDP и запрет прикладных STREAM-данных на signaling-only пути в трёх фазах —
до появления direct, после отказа direct и при повторной пробивке.

Oracle (честная модель наблюдения):

- Счётчики байтов `poll_send`/`poll_recv` тестового транспорта видят
  ТОЛЬКО зашифрованные QUIC-датаграммы и НЕ различают STREAM/CRYPTO/ACK/
  NAT-кадры; пригодны лишь для оценки общего объёма по пути, но НЕ
  как доказательство «ноль STREAM».
- `path.is_selected()`/`rtt` — не доказательство маршрута всех данных;
  application-level недоставка не доказывает отсутствие wire-утечки.
- Независимый oracle — на уровне decoded frames: (a) test-only trace-хук
  до шифрования с привязкой к пути, либо (b) захват wire-трафика
  с test-only ключами и декодированием пакетов. Само существование
  такого хука/доступного декодирования в iroh 1.3.0 НЕ подтверждено —
  возможность полноценного oracle это ОТДЕЛЬНОЕ условие P03
  (пункт матрицы «проверить доступность oracle-механизма» ниже).
- Для кандидатов NAT — наблюдение декодированных служебных кадров,
  а не рост счётчика.
- Обязательная негативная калибровка: контрольный эксперимент, где
  STREAM ЗАВЕДОМО разрешён через custom transport, должен подтвердить,
  что oracle обнаруживает нарушение; без позитивного срабатывания gate
  не пройден.
- Остановка `poll_send` после появления direct НЕ засчитывается
  как решение контракта.

## 2. NAT-матрица

Управляемый стенд фиксирует типы NAT-сценариев (полный cone,
ограниченный cone, port-restricted, симметричный). Для конфигураций,
где direct непробиваем (например симметричный NAT с обеих сторон без
UDP-holepunching), прямое соединение НЕ гарантируется. В режиме signal
альтернативный путь — конечное контролируемое согласование/ограниченное
ожидание, затем управляемый отказ; standby — переход на Yggdrasil
при его доступности, иначе отказ. Локальные
TCP-сессии не обязаны переживать закрытие QUIC-соединения; после обрыва
клиент устанавливает новое соединение.

|---|---|---|---|---|
