## 1. Required leaf contract

Preserve public API, exact visibility/signatures: `pub type Alphabet = [char; 256]`; `pub trait Base { const ALPHABET: Alphabet; fn get_index(c: char) -> Option<u8>; fn decode(input: &str) -> Result<Vec<u8>, DecodeError>; fn encode(input: &[u8]) -> String; }` (decode/encode provided methods); `pub struct Emoji` implementing `Base`; public `DecodeError`. Preserve `Emoji: Debug + Default`, and `DecodeError: Debug + Clone + Display`; do not require additional error traits. Preserve private `DecodeError` fields named `codepoint: char` and `index: usize` (private-field construction remains encapsulated). Its exact Display is `{} at index {} is not part of the alphabet`, formatted with the offending scalar and zero-based Unicode-scalar index, not UTF-8 byte offset. Keep no_std with alloc. Preserve conversion into `multibase::Error::InvalidBaseString`.

Each byte maps to exactly one exact alphabet scalar; preserve leading zero bytes; no padding or normalization. Empty leaf input maps to empty output. Reject the first non-alphabet scalar exactly (including U+FE0F appended to an alphabet scalar) and report its scalar index. Decode performs two bounded passes: count Unicode scalars, allocate the exact returned Vec capacity/length (m scalar slots for m input scalars), then decode once and report the first invalid scalar/index. Valid nonempty decode has exactly one output Vec allocation; empty decode allocates none. Encode computes exact UTF-8 output capacity in one pass over n bytes, then emits in one pass; valid nonempty encode has exactly one output String allocation, empty encode allocates none. For this alphabet, each scalar is 3 or 4 UTF-8 bytes, so capacity is between 3n and 4n; use checked size arithmetic and never wrap/truncate. Both directions use O(1) auxiliary space and no per-scalar allocation or dynamic map. Lookup uses fixed storage with O(1) or bounded O(log 256) work; if binary search over 256 entries is used, allow at most 9 scalar comparisons. Preserve the infallible `encode -> String` signature: overflow/allocation failure follows Rust's allocation-failure behavior (panic/abort as applicable); do not add a fallible API.

## 2. Observable consumer behavior

Multibase owns prefix 🚀 and consumes one Unicode scalar before leaf decode. `multibase::encode(Base256Emoji, []) == "🚀"`; decoding `"🚀"` gives empty bytes; `"🚀🚀"` gives `[0]`. Empty whole multibase input remains `InvalidBaseString`; unknown prefix `?` remains `UnknownBase('?')` (`c` is a known Base32PadLower prefix). Preserve all wire/parser capabilities. Do not change `/p2p` or `/ipfs` fixed unprefixed Base58BTC behavior. `/certhash` continues to accept multibase input and emit canonical Base64URL output. Pinned multiaddr `protocol.rs` parses `certhash` via `multibase::decode`; replacement must not affect that parser or introduce protocol changes.
