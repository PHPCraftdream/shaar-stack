# Native Mainline address-lookup contract (proposal)

**Status:** researched dependency additions and narrow ownership repairs have been approved by a human. The parent selected cache requery, address, caller-deadline and terminal-clock policies; resource caps remain proposed. This document's implementation policy remains pending parent review. It is a design proposal, not an implementation or runtime-readiness claim; no tests have been run for this document.

## 1. Scope and delivery

Provide signed, bounded address discovery over Mainline/pkarr for an explicitly expected peer key. Discovery only: no application data, public-data route, custom `#213` address, or Yggdrasil v1. Publication is an explicitly supplied approved snapshot, never addresses harvested by observing or binding sockets. Both IPv4 and IPv6 may be in the signed payload although the researched candidate DHT socket is IPv4.

Preserve the selected upstream primitives and narrow repairs; do not rewrite DHT. Acceptance tests and implementation follow policy review. Do not infer production/runtime readiness from design or narrow tests.

### Source observations

- `n0-mainline` `src/dht.rs`: `Dht::new` (139–143) spawns actor without retaining join handle; finite inbox (256) does not bound all retained GET/waiter work. `src/actor.rs` (413–435) shows the corresponding retained-work paths. `get_mutable_most_recent` (`src/dht.rs:445–463`) replaces only for larger value at the same sequence and misses greater sequence; application owns ordering/validation.
- `n0-mainline` `src/actor.rs`: synchronous `ToSocketAddrs` bootstrap resolution (45–60), public defaults, flush/select and loop shutdown (397–450) do not establish joined shutdown. Explicit numeric bootstrap injection is required; no defaults.
- Adapter `src/lib.rs`: Arc ownership (85–104), clone/spawn (336–339), loop owning self (265) risk a cycle. Failed/empty updates (325–334) can leave old task; paths (269, 295) may republish unchanged timestamp. Narrow lifecycle repair only; retain handles and prove shutdown.
- Adapter verification (54–63) is not sufficient authorization for dialing; explicitly bind returned key to expected key.
- `iroh-dns` DNS payload/value limit is 1000 raw bytes; `1000:` prefix for 1000 raw bytes adds five bytes, so the bencoded byte string occupies 1005 bytes before the `1:v` dictionary field and other KRPC overhead. The full signed packet adds 104 bytes (32-byte key, 64-byte signature, 8-byte timestamp), max 1104. `n0-mainline` KRPC receive buffer is 2048; reject serialized datagrams over 2048 before enqueue. Never silently parse truncated prefix. Parser allocation/depth/truncation behavior remains to verify. `n0` salt64 is a separate salted profile; this contract uses unsalted mutable values.
- Standard mutable signature preimage is exactly unsalted `3:seqi<timestamp>e1:v<length>:<DNS bytes>` (`iroh-dns/src/pkarr.rs:291-295`; mutable 145–156). Envelope contains key, signature and timestamp; adapter adds no salt or domain. Network `handle_response` (143–175) calls mutable verification (80–108): signature verification followed by `sha1(key || salt) == target`, not exact key equality. Use checked `SignedPacket::from_bytes`; unchecked conversion is not sole trust boundary. Exact conversion APIs are `TxtAttrs::<IrohAttr>::from_pkarr_signed_packet` and `to_pkarr_signed_packet`; locate their module through `iroh-dns/src/attrs` declarations. Establish independent reference fixtures before codec claims. Upstream `endpoint_info.rs:273-275` excludes relay addresses while including custom addresses; this proposal explicitly rejects both relay and custom variants.

## 3. Key, payload and address policy

1. Caller supplies exact expected 32-byte public key and bounded publication snapshot. Use only identity key material already owned by SDK; no seed accessor or public signer abstraction.
2. Check encoded bounds before costly parsing; reject malformed, truncated, unsupported or over-budget records whole. Verify signature, compare verified packet key byte-for-byte to expected key, validate freshness/sequence and decode all payload before dialability. Any failed check means no address and no dial.
3. Admit only explicit `TransportAddr::Ip` variants with nonzero port and the existing SDK native address predicate: canonical IP must not be unspecified, multicast, or IPv4 `255.255.255.255`; IPv6 `fd15:070a:510b::/48` is denied. The predicate permits private, loopback and LAN addresses, subject to exact-key authentication and allowlisting. This is not global-only and does not hide IPs. The source predicate does not itself check scope ID, flowinfo, or IPv6 link-local; for portable signed records this profile separately requires IPv6 scope ID and flowinfo zero and rejects `fe80::/10`, which needs an unapproved zone contract. IPv4-mapped IPv6 uses its canonical equivalent for policy/deduplication while preserving the declared canonical accepted value; do not invent wire encoding. Reject relay/custom/multiaddr. Publish only an explicitly supplied approved usable-unicast snapshot; withholding means no snapshot, not a private-address filter. Never harvest observed/bound addresses.
4. At most four native addresses; this limits snapshot growth but does not guarantee a 1000-byte fit. The actual encoder must independently enforce the 1000-byte limit including name/TXT overhead; reject excess snapshot atomically.

## 4. Freshness, ordering and cache

Values are proposed local rules; upstream behavior and guarantees are distinguished below. The selected upstream primitives are not modified; these bounds are application policy:

- Maximum signed age 300 seconds; future tolerance 30 seconds; boundaries inclusive. Use checked integer microseconds, reject overflow/unrepresentable values. Reject negative sequence and above `i64::MAX` before casting.
- Publish with a new signed timestamp every 60 seconds; never refresh by cloning the old signed item. DNS TTL is a cache hint, not freshness authority.
- A completed new query that performed network work may accept an identical, still-signed-fresh same-sequence record and renew the cache receipt deadline. With query-completion monotonic receipt `R` and sampled wall time `W`, deadline is `R + min(30s, max(0, 300s - max(0, W - signedTime)))`, using checked integer microseconds. Recheck wall age on every use; never alter signed time or resurrect age-expired data. Signed age exactly 300s is accepted, but yields zero positive cache lifetime: it can be used only as the immediate query result at that boundary and must be re-queried thereafter. Cache expiry prohibits cache use and triggers a bounded real network re-query; cache hits and identical duplicates within one query/response never extend the deadline. A duplicate query cannot clear conflict or lower the watermark; signed age remains authoritative. Local active-PUT replay or cached responses alone do not qualify as network work. Owner-lifetime high-water state (sequence, full winner bytes and conflict marker) is independent of renewable cache receipt and is never evicted, lowered or cleared by expiry.
- Compare owner wall and monotonic clocks; detected backward wall-clock event clears usable cache, stops publish/resolve for this owner with explicit clock error, and retains replay state for remaining owner lifetime. Owner enters terminal clock-fault state; it never automatically recovers or resumes on clock catch-up. External clock correction requires explicit restart/new owner, which loses process-local watermark; persistent replay defense is not promised. No public clock API is exposed.
- Publisher timestamp is `max(wallMicros, last + 1)` with checked arithmetic, only if result is no later than `wallMicros + 30s`; otherwise fail closed. For a normal, nonfaulted owner, if publishing clock is behind the previous remote sequence, publication fails until it catches up; do not fabricate persistence or automatically overwrite. This catch-up behavior never resumes an owner in terminal clock-fault state; explicit new owner is required.
- Complete the bounded query before dialing. Select greatest sequence; equal-sequence conflict is evaluated only at current maximum. Track greatest sequence, full winner bytes and conflict marker for 64 expected keys; never evict, including after cache expiry. Lower than watermark is rejected; a lower sequence than current winner does not poison it. Conflicting valid values invalidate that key at its current maximum. A strictly greater sequence clears conflict for the superseded sequence. First operation may detect conflict and fail rather than return an earlier hit. Never wait unboundedly for conflict discovery.

The 300s age, 30s future/cache bounds, 60s publication and fixed fixture budgets are conservative local choices, not performance proof. Older upstream hourly records with unchanged timestamps become rejected after 300s. Equal-conflict handling is stricter than upstream lexicographic tie behavior; wire format is unchanged.

## 5. Admission, memory bounds and deadlines

These are hard aggregate ceilings, including actor maintenance—not aspirational counts. On capacity exhaustion stop the operation terminally, count/release its resources, and return explicit error. No unbounded/adaptive server behavior.

| Resource | Ceiling and behavior |
|---|---|
| Addresses / peer state | 4 addresses/snapshot (bounds growth; independent encoder size check required); 64 peer slots (bounded state). Each stores sequence, renewable cache receipt deadline, protected winner full bytes <=1104 and conflict marker; no eviction. |
| Operations / queues | 8 operation slots total (bounded concurrency); 16 queued requests (bounded waiting), each payload <=1104 bytes plus fixed-size controls. Overflow rejected. Queued status is explicit: queued, admitted, rejected/terminal. |
| Candidate / visited | 256 candidates and 256 visited entries TOTAL per owner (limits hostile referrals), fixed-size entries; no per-operation multiplication. |
| RPC / maintenance | 128 inflight RPCs aggregate, including maintenance; max 16 per operation. At most one maintenance operation admitted, sharing slots, deadline, queues and budgets. Initial implementation is client-only: no responding server in native lookup scope; narrow switch prevents re-enabling after 15 minutes. |
| Outbox | 128 datagrams aggregate, each serialized <=2048 bytes, reject before enqueue. |
| Results | 8 result channels, max 32 entries and 65,536 bytes per operation. |
| Values | DNS payload/value <=1000; full signed packet <=1104. Reject oversize/truncated whole input. |
| Time | Caller has 10 seconds from request for queue wait, bootstrap and attempts; cleanup is separate. Close has a 5-second failure/reporting boundary, not a guarantee of completed cleanup; success requires observed join. |

At most three network query rounds or PUT attempts total per operation under the original caller deadline, with full-jitter backoff bounded by 100ms then 200ms. No per-RPC recursive reset. Publication retries exhausted: wait for next 60-second tick and coalesce missed ticks; never extend deadlines or resource ceilings.

Bootstrap must be injected numerically from owned fixtures: nonempty, at most four numeric IPv4 socket endpoints, nonzero ports; loopback is allowed for owned fixtures. Validate before bind. No public/system DNS defaults, hostname resolution, or public network traffic in owned CI; no public network operations are approved. Production bootstrap choice is deferred to review and must not hardcode fixtures into the public product. The absence of n0 HTTP is a source observation only; a future receipt oracle for destinations is required. DHT sender IP exposure is explicit and not anonymized.

At the 10s caller deadline, if no successful result exists, signal stop and report caller timeout. A successful result must be committed before the deadline; at or after the deadline no successful result may be committed. The actual operation remains charged and its JoinHandle retained until cleanup is observed; cleanup time is not charged to the caller deadline. Do not start a new deadline/retry, busy-loop or detach. At the 5s close reporting boundary, report failure only if actual handle cleanup has not been observed; success requires observed join. Cancellation while queued but not admitted removes the entry, releases its buffer and starts no work. Before enqueue cancellation starts no work. On close timeout the actual owner retains the cleanup handle and resource charges until observed terminal completion; no detached ownership. Cancellation after admission does not release capacity until terminal cleanup; admitted work remains counted. Resolve cancelled before completion must not publish address, cache, or dial from its completion. No lock across await/callback. One logical writer per key is an operational premise for publication ordering, not a protocol guarantee. No strong self/task cycle or discarded `JoinHandle` is permitted. Drop fallback may abort but is not joined success.

The SDK coordinator retains the actual DHT actor stop signal and completion JoinHandle, not only a wrapper task. Successful close requires observed actor completion and socket destruction; retained client handles are inert and cannot retain the socket. Socket rebind is the owned-fixture completion oracle. A timeout around a caller does not cancel admitted dependency work.

## 6. Publication, withdrawal and cancellation

Each update has a generation. Empty, withheld, invalid replacement or explicit stop revokes active generation before replacement validation. An update acknowledgement transfers the validated snapshot to its owner; requester cancellation before acknowledgement triggers revoke/generation cleanup, while after acknowledgement background publication intentionally persists until explicit withdrawal/close. Withdrawal prevents further sends by revoked generation after successful acknowledgement; drain/observe admitted send cleanup. Already-sent packets cannot be retracted; acknowledgement does not erase remote DHT caches. Invalid replacement cannot leave old snapshot refreshing. `no_publish` does not mean no bootstrap/network traffic or anonymity.
