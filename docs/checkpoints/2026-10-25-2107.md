## New source result #87 — decisive next input

### Established counterexample, not historical CI cause

SDK `connect_route` получает permit и ждёт Iroh connect внутри 10 s timeout. Iroh сначала посылает ResolveRemote и ждёт oneshot, и только затем создаёт Noq connection. Если обработка ResolveRemote задержана до срабатывания SDK timeout, SDK законно возвращает Deadline, permit и future исчезают, а новая Noq connection вообще не создана. Поздняя обработка actor message не возобновляет уже dropped SDK future. Server.accept ждёт Initial, который этот attempt никогда не отправит; unconditional tokio::join удерживает этот observer после outbound error и дожидается outer25 s.

Следовательно public API не обещает ни новый inbound Session, ни native UDP witness при каждом failure. Это конкретный допустимый schedule, не утверждение, что Windows действительно задержал actor на10 s.

Дополнительный дефект oracle: blackhole адрес передаётся Iroh ДО handshake; когда selected route отсутствует, Initial может рассылаться по known hints, включая blackhole. Любой nonempty UDP поэтому не доказывает вызов SDK native finalization.
