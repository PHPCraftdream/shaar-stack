## Caller defect and written repair

Both original composed branches construct a pinned async shutdown waiter but perform `role.start().await` before polling it. Tokio console listener setup lives inside that future, so a pending DHT/Ygg startup neither observes shutdown nor registers the expected async signal wait. This mechanism was established by source reading, not a live smoke or externally injected OS-signal experiment.

Each main.rs now has private `start_until_shutdown<T>` over two futures. `tokio::select! { biased; () = shutdown => None, result = startup => Some(result) }` polls shutdown first. The caller stores the result before borrowing the role again: `Some(Ok(()))` runs the role, `Some(Err(error))` retains the startup error, `None` skips run. The existing unconditional `role.shutdown().await` and signal failure collection then execute. ServerRole::start explicitly documents cancel-safe retained phase ownership in role/server.rs; the shared role module documents the same retained lifecycle for both roles.

Each binary adds these four test identities under `startup_tests`:
- `ready_shutdown_is_polled_before_startup`
- `shutdown_drops_a_pending_startup_waiter_without_waiting_for_it`
- `successful_startup_retains_the_registered_shutdown_waiter`
- `startup_error_is_returned_without_replacing_its_cause`

They use stack-pinned futures, oneshot control and a Drop counter, not busy readiness polling or new network/proof infrastructure. The pending-start cancellation has a five-second safety timeout, not a performance criterion. They are WRITTEN and COMPILED BY CLIPPY, NOT locally executed or CI-accepted. Expected package inventory grows 12 -> 16 per binary, but actual selected/executed counts must come from CI.
